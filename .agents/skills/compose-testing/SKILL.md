# compose-testing

Начни с пользовательского действия и проверяемого результата. Для `Content` используй `@get:Rule val composeTestRule = createComposeRule()`. В `setContent` передай тему, фиксированный `UiState` и обработчик, сохраняющий полученное событие. Найди элемент по семантике, выполни действие и проверь его эффект. Например, введи вес порции и проверь значение в отправленном событии. Отдельно проверь отображение рассчитанной суммы при передаче нового состояния.

Запусти новый тест до реализации и проверь причину падения. После каждого изменения UI самостоятельно запускай относящиеся к нему тесты с `composeTestRule` в пределах согласованного прогона. Выбери команду по расположению теста. В примерах замени модуль и полное имя класса на фактические.

```powershell
# Локальный тест в src/test, включая Compose при настроенном Robolectric
.\gradlew.bat :app:testDebugUnitTest --tests 'example.FoodContentTest'

# Инструментальный тест в src/androidTest на устройстве или эмуляторе
.\gradlew.bat :app:connectedDebugAndroidTest '-Pandroid.testInstrumentationRunnerArguments.class=example.FoodContentTest'
```

Для проверки макета с уже подключённым Paparazzi или Roborazzi найди задачу варианта через `.\gradlew.bat :app:tasks --all`. Обычно это `:app:verifyPaparazziDebug` или `:app:verifyRoborazziDebug`. Используй фильтр класса, если задача его поддерживает. При расхождении изучи изображение разницы. Обновляй эталон только для согласованного визуального изменения. В отчёте укажи фактически выполненные проверки и недоступные условия запуска.
